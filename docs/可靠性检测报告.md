## 一、架构调整（方式 A：检索即服务）

### 1.1 产品定位修正

**之前（错误）**：`/ask` 一体化——rag-service 内置 LLM 汇总，需配置 ARK_API_KEY。

**现在（正确）**：rag-service 是**纯检索服务**——只包含 embedding 模型，不含生成模型、不含 LLM API key。生成由接入方 Agent 自带 LLM 完成。

### 1.2 正确的整体请求流程

```
用户 ──→ harness（Reasonix / Claude Code / Hermes）
            │
            ▼
        LLM 主模型（agent 的大脑）
            │  ① 判断：话题可能记录过 → 决定查知识库（Tool use）
            ▼
        POST /search {"query": "..."}（HTTP 工具调用）
            │  ② 只传 query
            ▼
   [rag-service：embedding 向量化 → 混合检索(向量+BM25+RRF)]
            │  ③ 返回 top-k 片段（来源+内容+分数）
            ▼
        LLM 主模型
            │  ④ 片段插入自己的 prompt，重新推算
            ▼
        最终回答 ──→ 用户
```

**职责边界：**
- rag-service：第 ②③ 步（检索）——**产品只含 embedding 模型**
- Agent 的 LLM：第 ①④ 步（判断 + 生成）——模型/API key 归 Agent 自己
- 任何 LLM（OpenAI/ARK/本地）都可复用同一检索服务

### 1.3 调整内容

| 项 | 调整 |
|---|---|
| `/ask` | 降级为可选一体化模式（需自备 ARK_API_KEY），非主路径 |
| `/search` | 主路径：检索服务，供 Agent 作为工具集成 |
| 新增 | `Agent集成指南.md`（工具注册 / 调用注入 / 可靠性约定） |
| 产品文档 | 定位更新（方式 A，不含 LLM key） |

## 二、生产可靠性检测结果

### 2.1 检测方法

- 真实服务（uvicorn :8931，583 chunks，双数据源）
- 模拟 Agent 调用视角（HTTP /search）
- 12 项 pytest 断言（test_reliability.py）+ 实机验证（重启/懒加载/ingest）

### 2.2 检测结果（15/15 通过）

| 维度 | 结果 | 详情 |
|---|---|---|
| **检索准确性** | ✅ 5/5 | PARA→Tiago、P8→P8、KV Cache、常绿笔记→Andy、密度→Andy 全部命中正确来源 |
| **无匹配不编造** | ✅ 3/3 | 天气/排序/电影 → filtered=true 或 hits=0（不返回伪造内容） |
| **边界输入** | ✅ 3/3 | 空查询 422、超长查询 422、特殊字符正常 |
| **并发独立** | ✅ 2/2 | 10 线程混合查询：无报错、每请求结果结构完整（无串扰） |
| **性能** | ✅ | 单请求延迟 29-66ms，并发 10 请求总耗时 353ms（平均 35ms） |
| **重启恢复** | ✅ | 服务重启后懒加载索引，首次查询即命中 |
| **/ingest** | ✅ | 无变化快速返回（added=0） |
| **自动更新** | ✅ | 文件变更→局部增量→可检索（pytest test_partial_ingest 隔离验证） |

### 2.3 关键可靠性语义（Agent 必须理解）

1. **hits 是候选不是结论**：分数阈值无法替代语义判断——相关性由 Agent 的 LLM 判断（检索层召回、LLM 判断的分层设计）
2. **无匹配不编造**：`filtered=true` 或 `hits=[]` 时，Agent 应正常回答，不虚构知识库内容
3. **来源可追溯**：每片段带 file/section/score，回答可注明出处
4. **检索失败不阻塞**：/search 报错时 Agent 应忽略并正常对话

## 三、结论

1. **架构**：方式 A（检索即服务）符合产品规划——纯检索、单 embedding 模型、无 LLM key 依赖、可被任意 Agent 复用
2. **可靠性**：生产环境全流程 15/15 通过，含准确性/无匹配/边界/并发/重启/自动更新全维度
3. **可交付**：检索服务可投入生产；Agent 按 `Agent集成指南.md` 接入即可
4. **遗留**：systemd 部署需在可写 /etc 环境执行（本环境只读）；deb 打包（GitHub 交付）待启动
